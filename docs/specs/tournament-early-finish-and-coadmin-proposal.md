## 7. 提前收赛

现状：squad_doubles达到target_wins可自动把无分比赛标canceled；其他模式按预设总场次结束。`submitScore/logic.js`的reviveScorelessCanceledMatches会在更正比分时复活所有无分canceled，因此不能只加一个“结束”按钮并复用这个状态。

建议范围：仅赛事主办者在running时主动提前结束，至少已有一场有效完成比赛。沿用finished赛事的排名/战报/分享入口；其他人没有该动作。独立打水无结束按钮的合同不变。

- 入口拟放赛程现有管理区域，次级动作“提前结束比赛”；确认显示“已完成X场，剩余Y场将取消。排名只统计已完成场次。”
- 已完成比分和录分人保留；未完成比赛标canceled并存独立原因manual_finish，取消不是负场、不是0比分；记录finishMeta的manual类型、操作者、时间与幂等请求，增加赛事version。
- 保存中比分与提前结束并发必须通过赛事事务写冲突线性化：先完成的有效比分进入最终结果；提前结束先提交时，后续未完成场次拒绝录分。存在有效录分锁时默认阻止结束并提示等待，仍要测试“读锁后新申请”的竞态，不能把单次读锁当原子排他。
- 更正已完成比分仍按既有权限进行；manual_finish场次不能被更正比分的自动复活逻辑恢复，赛事仍保持finished。规则自动取消维持现有可复活语义。
- 不新增“撤回提前结束”。既有主办者重置比赛依旧是独立的清比分动作；clone/reset不得携带manual finishMeta到新开赛。
- 未录一场时保持既有删除/重新配置流程，不用提前结束产生全员零场排名。

可比较的另一范围是“允许零场结束”：它需要finished空战报、全员零场排名、分享说明及本机完成快照口径，成本/验收范围更大。另一个决定是是否需要保留比分的重新打开；这会新增状态迁移与锁/排名/分享合同，不能默认附送。

离线规则样例（预期，非实现通过回执）：

| 输入 | 预期 |
| --- | --- |
| 6场中2完成、4待录，主办结束 | 2比分保持、4 manual_finish canceled、finished；排名恰等于这2场统计 |
| 上例更正第1场比分 | 两场结果重新算；4场不复活；仍finished |
| squad规则取消后更正致未达目标 | 保留原自动恢复规则；不与manual取消混用 |
| 同一结束request重复/并发两次 | 同一结果，version与审计仅一次；新request不能再次取消或变更原因 |
| 非主办/草稿/全零已录/活跃录分锁 | 分别拒绝，比分、状态、version不变 |
| 更正/录分与结束交错 | 最终可串行解释；不能报失败但提交了半套结束数据 |

## 8. 协管与裁判

现状：creatorId为主办者；实际绑定参赛者也可录分，指定refereeId当前只是分工，**没有裁判独占录分**。导入guest的姓名相同不等于微信身份绑定。反馈“无法添加管理员”不能用指定裁判来冒充解决。

建议最小协管范围：主办者从已实际加入并绑定身份的参赛者中授予/撤销协管；无自由输入openid，没有同名自动匹配，不自动转移主办身份。新角色不改变普通参赛者已有录分权。

| 动作 | 主办 | 协管（建议） | 绑定参赛者 | 指定裁判但未绑定参赛者 |
| --- | --- | --- | --- | --- |
| 草稿配置、名单与分队、开赛、裁判分工 | 是 | 是 | 否 | 否 |
| 录分/更正 | 是 | 是 | 是（原合同） | 不从标签单独授予 |
| 授予/撤销协管、转移主办 | 仅主办授予/撤销；本轮无转移 | 否 | 否 | 否 |
| 删除、重置、提前结束 | 是（提前结束须第7方案批准） | 否 | 否 | 否 |

上述矩阵描述已批准的业务权限。当前 `setReferee` 是保留的后端能力，客户端未提供裁判分配入口；前端交付的是协管授予/撤销与配置、名单、开赛入口，不把后端可调用解释为裁判界面已经完成。对应事实见 `miniprogram/permission/permission.js` 的 `canEditScore` 与 [详细状态](../tasks/paused-plan-status.md)。指定裁判仍不是独占录分角色，普通绑定参赛者原有录分权限保持不变。

权限实施候选：保留现有isAdmin的“主办”意义，另加显式管理能力函数，仅替换被批准的配置/名单/开赛入口；禁止一次把isAdmin扩成协管导致删除/重置权限一起放大。授予/撤销必须校验getWXContext和权威名单、事务version、幂等、受限操作审计；角色撤销后新调用即失效。已打开页面按最新角色刷新，不凭本地按钮显示作为安全检查。未来若需要裁判独占录分，要另选方案并给既有参赛者变化明确说明。

入口拟放草稿大厅现有成员管理，已加入成员显示身份绑定状态及“协管”标签；主办可授予/撤销，协管只能查看自己的能力说明。比赛开赛后是否允许授予/撤销建议允许主办操作，但不因此允许改赛程或已确定的配置。角色新授予需真实绑定成员，不能导入名单后隐式赋权。

离线权限样例（预期，未运行新增角色代码）：主办授予B后B可配置/开赛但不可删除/重置；B不能自授/授予C；主办撤销B后B管理动作拒绝，B作为真实参赛者仍保有原录分权限；C伪造coManagers/event.openid/同名guest均不能获得管理权。名单移除与撤销/开赛并发要有明确顺序且不存在悬空协管。
