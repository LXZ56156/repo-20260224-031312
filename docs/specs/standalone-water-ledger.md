# 独立打水账本产品规格

> 状态：已按逐点审批实现至 `c2f438a`。本文记录当前已批准行为，不授权新增 CTA、生命周期、权限、云写入或发布语义。

## 目标与入口

独立打水用于“不创建比赛也能快速记水”的轻量场景。入口位于 `pages/launch/index` 的“快速打水”卡片，点击“开始记水”进入 `pages/water/index`。它不创建 `tournament`，也不改变创建比赛、赛程、录分、排名或复盘流程。

首次进入时先通过完整资料门禁（当前标准包含昵称、头像和性别），再使用昵称创建账本；同一发起人使用稳定账本 ID，已有 active 账本时继续该账本。账本标题按首次创建日期生成，例如“8月8日打水局”，不会每天自动新建。

## 角色与权限

| 角色 | 能力 |
|---|---|
| 发起人 | 添加球友、邀请、记一局、直接加减水、撤销上一条、查看账本 |
| 受邀球友 | 使用自己的昵称加入，或认领一个尚未绑定的预添加名字；加入后继续查看账本 |
| 未加入访客 | 知道账本 ID 即可查看；可选择昵称/可认领名字并确认加入，但不可记账 |

发起人页面只有一个显式“邀请加入”按钮，使用 `open-type="share"`，路径为 `/pages/water/index?id=...`。云端以 OpenID 判断发起人和认领关系；除 `join` 外的名单及记账写操作只允许发起人。返回给客户端的数据不暴露 owner/participant OpenID，只返回 `claimed`、`isViewer`、`isOwner` 和 `viewerParticipantId`。

认领预添加名字不会增加人数；使用自己昵称加入会新增一人，账本已满 24 人时拒绝。同一 OpenID 已在名单中时不会再添加第二人。

## 名单

- 每个账本最多 24 人，发起人创建时自动成为第一位球友。
- 手动添加支持换行、逗号、顿号和分号分隔；名字清理后最长 20 个字符，同一批及现有名单按不区分大小写去重。
- “导入接龙”复用 lobby 接龙解析规则，过滤常见活动/付款噪声；写入前显示识别人数、重复人数、超出名额人数、最多 8 个预览名和实际新增人数。没有新名字时不可提交；提交仍复用 `addParticipants`，写入 `source=manual`，不存在独立 relay 数据类型。
- 记一局的总人数超过 8 人时才显示本地姓名搜索与清除按钮。搜索是不区分大小写的姓名包含匹配，不支持拼音/模糊搜索，也不搜索总账；过滤、清空或轮询刷新不会清除仍有效的胜负方选择。

## 记一局

- 只要求名单至少 2 人，不要求 4 人。胜方和负方各至少 1 人、人数必须相同，支持 1v1 及等人数多人对阵，也不要求名单中所有人参赛。
- 点姓名会把球友分到当前激活的一方；同一人不能同时属于两方，可移动或取消选择。
- “每人水数”使用微信原生 `picker mode="selector"`，范围 1–99，默认 1。
- 提交后，每位胜方增加对应“赢水”，每位负方增加对应“请水”。

## 直接加减水

发起人可在总账中直接点某人的 `＋` 或 `−`：

- `＋`：表示所选另一位球友请该球友；
- `−`：表示该球友请所选另一位球友；
- 弹层明确显示“算在谁头上”的 selector，默认选中第一位其他球友，用户可再切换；水数同样使用原生滚轮，1–99，默认 1。

名单至少有两人才显示直接调整能力。

总账口径固定为 `净水 = 赢水 - 请水`，按净水、赢水、姓名排序。所有条目的净水合计应为 0；界面当前仍显示“总账差”用于观察该守恒值。

## 最近记录与撤销

- 比赛记录显示“胜方 胜 负方 · 每人 N 水”；直接记录显示“甲 请 乙 · N 水”。
- 完整 entries 用于计算总账，界面只显示最后 4 条并按新到旧排列。发起人可在确认弹窗后撤销最末一条，不能选择性删除更早记录，也不能撤销添加名单或认领。
- 每个账本最多 200 条记录。达到上限时云端拒绝继续写入；当前没有获批的新账本生命周期 UI。

## 同步与写入安全

- 页面可下拉刷新；可见时每 8 秒补拉一次，返回前台时立即补拉，隐藏/卸载时停止轮询。
- 客户端忽略比当前版本更旧的响应；云端用 `expectedVersion` 做乐观并发检查，冲突后客户端强制刷新。
- 当前客户端所有写操作都会携带 `clientRequestId`。相同操作在不明确失败后重试复用同一 ID，payload 改变或成功后换新 ID；云端保留最近 20 个 ID 并返回 deduped 结果，避免重复记账。服务端 `create` 接受 ID 但不强制，其他 mutation 强制要求。
- 页面级 guard 覆盖资料门禁、确认弹窗和网络请求，防止重复点击并发写入。

## 数据与云合同

- 云函数：`waterSession`；集合：`waterSessions`。
- 该集合独立于 `tournaments`；打水流程不读取或写入赛事文档。
- 对外 action：`create`、`get`、`getMineActive`、`join`、`addParticipants`、`recordGame`、`recordDirect`、`undoLast`。
- 当前页面不调用 `getMineActive`；该 action 只按稳定 ID 读取，并未校验 status，不能因命名推断它只返回 active。
- 云端保留 `finish` 兼容分支和 mutation 的 `active/finished` 状态校验，但当前客户端没有 wrapper 或结束入口。不得把兼容分支解读为已批准能力，也不得擅自删除它。
- 云函数曾在本轮一次性授权下部署并核验；后续部署、真实数据验收和发布仍需新的明确授权。

主要文档结构：

```text
waterSessions/{stableOwnerSessionId}
  ownerOpenid, title, status, version
  participants[]: id, name, source, openid, createdAtMs
  entries[]:
    game: winnerIds, loserIds, unitsPerPlayer, id, createdAtMs
    transfer: fromPlayerId, toPlayerId, units, id, createdAtMs
  recentRequestIds[]
  createdAt, updatedAt, updatedAtMs
```

## 明确不做

- 不要求凑满 4 人，不依附 tournament，不新增赛程、排名或结算流程。
- 不提供用户可见的结束、完成、另开账本或历史账本管理入口。
- 不新增球友删除/改名、管理员转移、受邀人记账、重置或选择性删除记录。
- 不把搜索扩展到总账或添加名单。
- 不自动恢复 Next-Gen/C3、Home 重做、全局设计系统或跨页面统一。
- 不因本规格自动改变 CTA、导航、文案、权限、分享、云写入或发布语义。
