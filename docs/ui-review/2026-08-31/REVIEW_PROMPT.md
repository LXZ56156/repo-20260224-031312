1. 必须逐张打开并查看全部 136 张原始 PNG，不得抽样，不得只看缩略图、拼图或少量代表页面。
2. 必须建立 136 行“截图覆盖留痕表”：每张图一行，写完整相对路径、页面、业务状态、已检查标记和关联问题 ID；没有问题也要写“检查无异常”。禁止用“同类图片略”代替。
3. 滚动分段图既要逐张检查，也要按同一页面连续状态合并判断，不能只看首屏。

6. 写明资料名称、链接和访问日期，区分平台约束、可用性/无障碍准则、视觉参照、审美判断和推断；调研结果必须实际反映到建议中。
7. 如果无法联网、无法打开全部图片或无法核对源码，应停止并报告缺口，不能输出伪装成全面评审的部分结论。

## 第一轮：基础质量与可用性

不能只检查一致性，必须检查：

- 信息层级、操作显著性、按钮主次和动作分组；
- 至少 44px 触达、对齐、间距、文字基线、换行、截断和横向溢出；
- 页面滚动、弹层滚动、safe-area 和键盘影响；
- 文字、背景及禁用关键 CTA 的可辨认性；
- 空态、错误态、加载态、busy、禁用、只读、权限和筛选状态；
- 长列表、高密度名单、搜索空态和弹层；
- 状态反馈是否及时、是否误导、是否造成页面跳动或视觉噪声。

## 第二轮：审美、视觉体验与适度改造

基础检查后必须继续完成：

- 评价第一印象、整体页面气质及运动产品气质是否成熟、清爽、有节奏；
- 检查版式比例、视觉重心、留白、字体层级、字号和字重；
- 检查颜色关系、圆角、边框、阴影、图标、卡片表面和信息密度；
- 特别审视所有按钮、chip、筛选项、危险动作和底部 CTA 是否默认组件堆叠、臃肿、笨重、模板化、争抢层级或缺少操作反馈；
- 按“创建 → 配置 → 开赛 → 录分 → 排名 → 复盘”和独立打水链路，串联评价扫读路径、操作连续性和视觉情绪；
- 给出明确视觉方向与理由，说明怎样改善按钮丑、按钮笨重、模板化和层级平的问题；
- 可以提出有证据的适度信息重组、按钮组合、组件或页面布局调整，但必须同时提供最小改法、适度改造方案、收益、成本和取舍；不得借机全面重做产品或引入新框架。

禁止只写“统一按钮样式”“统一间距”“建议优化”等空泛结论。

## 优先级

- P0：阻断关键任务、严重误导、权限/状态表达错误、明显不可操作或严重无障碍问题。
- P1：显著影响操作效率、主次判断、阅读理解或整体视觉体验，应优先修改。
- P2：不阻断使用，但能提升完成度、质感与一致性的细节。

不要把所有不一致机械判为高优先级，也不要用一致性替代审美和体验判断。

## 每条建议必须包含

- 唯一问题 ID 和 P0/P1/P2；
- 对应截图文件、页面、角色和状态；
- 对应源码文件及尽量精确的位置；
- 看到的具体证据；

- 最小修改方案；
- 确有价值时的适度改造方案、收益、成本及不过度的理由；
- 影响页面和状态矩阵；
- 业务、权限、交互和视觉回归风险；
- 可以实际验证的验收标准。

## 产品与实现边界

- 保留现有业务合同、权限语义、导航和核心流程。
- 这是个人项目；方案必须简单、直接、易维护，不引入设计框架、抽象层、兼容层、冗余测试或假设性兜底。
- 所有建议必须能用原生 WXML / WXSS / JS、系统字体和本地资产实现，不使用 Web 字体或远程视觉依赖。
- 考虑低端机、户外强光、reduced motion 和至少 44px 触达；触达尺寸按小程序逻辑 px/rpx 判断，不得直接用导出 PNG 物理像素下结论。
- 在线缓存先显和健康后台刷新必须静默，不得恢复“当前展示缓存数据”或同义提示；真实离线、写入失败和冲突提示可以保留。
- 暖米色+酸绿、暗底+荧光绿、报纸规则线，以及历史 Next-Gen / C3 / Home 全面重做均已否决，不得复用。
- 微信原生 modal、picker、键盘、系统分享、权限面板、Toast、Loading 等系统层应单列为真机人工检查项，不得假装已由普通页面截图验证。
- fixture 只证明页面渲染，不代表真实线上数据或云链路已执行。
