# 第12项：单打循环离线候选

在第7/8实现和隔离环境资格核对进行期间，主控验证已准备规则表的有限算法范围。用户“全部允许”不等于已获得反馈者/真实组织场景的需求信息；已异步询问人数、场地、时长、循环和排序。

新增 `cloudfunctions/startTournament/singlesRoundRobin.js`，目前只是未接入的离线候选。现有三模式枚举、创建/配置/开赛handler、客户端导航及生产状态均未用此算法；不把新增文件当新模式已可用。

候选验证2–6人、1/2场地、1/2循环（默认一循环）。每对球员每循环一次，奇数每人每循环轮空一次；轮空没有假比赛或0比分。场地不足时把同一逻辑轮拆成时间批次，同一批次每人最多一场；单人队伍长度1、全局matchIndex及roundIndex唯一，pending无比分，bye与某批次的休息人员分别表达。缺ID/重复ID/不足2人、非法参数及deadline到期明确拒绝，不返回半份赛程。

先行21项测试因新算法文件缺失实际失败；实现后21/21通过，0失败/跳过。参数化覆盖表格中全部人数/场地/循环组合，逐对校验覆盖、总场公式、同批次互斥、轮空次数、坐标唯一和无伪比分；含deadline/无效名单拒绝。定向eslint0错误/0警告。

未验证：真实使用需求、连续上场/休息偏好、最终最大人数/循环数，单打全链路模式注册/草稿配置/开赛/锁/录分/更正/排名/复盘/本机快照/分享/提前结束，真实云生成耗时及真实设备。现有双打4人完整性检查不能未经对应实现就改为接受单打，本候选没有关闭该检查。

后续在用户场景确认后接入完整显式mode合同并做最小原生入口；不得声称第12项完成或擅自部署/上传。
