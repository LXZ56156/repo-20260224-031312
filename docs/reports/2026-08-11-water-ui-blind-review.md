## 盲审 A

### 主要发现

1. 主 CTA 在真实图中只有约半幅宽且折成两行，属于写入动作的视觉验收阻断。
2. 12v12 摘要和长昵称同时截断，提交前无法复核完整阵容；V2 合同要求可展开查看。
3. 当前正在选择胜方还是负方不够显著，滚动后容易忘记操作目标。
4. 胜负计数在分段、摘要、名单说明和 CTA 中重复四次，真正的有效性状态反而不清楚。
5. 胜负为空或人数不等时，按钮仍表现为可提交，只在点击后 toast，反馈过晚。
6. 三列描边格、角落伪元素和单行硬截断形成“表格墙”，长昵称有选错风险。
7. picker、CTA 和大块底部留白没有形成一个稳定完成区。

### 建议

- 恢复历史标题提示、胜负分段、对阵摘要、单一名单和全宽短 CTA。
- 胜负状态同时使用显式文字、边框和浅填充，不只靠红绿或伪元素。
- 底部固定区只保留一次确定性摘要和单行动作按钮；无效阵容提前禁用并内联解释。
- 长昵称优先三列、两行截断并保留完整 accessible name。
- 24 人、12v12、20 字名字应作为第一验收状态，而不是最后补测。

## 盲审 B

### 主要发现

1. 主 CTA 的半宽几何和动态长文案是首要 P1；按钮应只承担动作名称。
2. 固定 `height: 88vh` 加多个固定模块，使 320、键盘或字体放大时中部选择区容易塌缩。
3. 390 使用三列导致 24 人需要八行；滚动条贴住右列，状态伪元素不可靠。
4. 相同状态重复四次，当前操作方不够突出。
5. 固定高度、nowrap 和 overflow hidden 对 130% / 160% 字体放大不安全。
6. Vant `safe-area-inset-bottom` 与 CSS `env(safe-area-inset-bottom)` 双重负责，造成底部空白并挤压名单。
7. 圆角、边框和高字重档位过多，所有模块视觉声量接近。

### 建议

- header / footer 固定，中部成为唯一滚动容器；使用 `max-height`，不固定 88vh。
- safe-area 只允许一个 owner。
- 390 / 430 恢复历史四列，320 三列；每格至少 44px。
- 主按钮单行“确认记一局”，阵容与水数独立显示在按钮上方。
- 使用明确字阶、最多三档圆角和有限阴影；负方红只用于小面积语义。
- 验收必须覆盖 320 / 390 / 430、字体放大、键盘、picker、搜索和错误态。

## 综合决策

### 两份审查的一致结论

- 问题根因是几何、层级、滚动和状态表达，不是单纯换颜色。
- 先恢复 `c2f438a` 已验证骨架，再做克制优化。
- CTA 必须全宽、单行、短文案；动态摘要不能塞进按钮。
- 选择状态不能只靠颜色或 `::before`。
- 顶部状态、底部提交固定，中部只有一个滚动 owner。
- safe-area 只能由一层负责。
- 失效阵容应在提交前禁用并内联解释。

### 分歧与处理

- A 建议长昵称压力态维持三列；B 建议 390 / 430 恢复四列。最终采用内容自适应：320 固定三列；390 / 430 普通昵称四列；检测到长昵称时自动三列并允许两行截断。完整姓名继续保留在 accessible name 中。
- A 建议直接恢复 Vant `block` 按钮；B 认为只需复刻已验证几何。最终保留当前原生按钮，使用 block-fill 几何和真实截图门禁，避免重新扩大组件范围。
- A 提议恢复旧 scoreboard 信息层级。该建议不采纳，因为会回退 V2 已批准的“总账 / 流水 / 球友”结构；只恢复弹层的层级和交互机制。

### 本次采纳的整改

- 恢复标题下规则提示、明确胜负分段、对阵摘要和紧凑单名单。
- 补齐合同要求的“查看完整阵容 / 收起完整阵容”。
- 胜负无效时禁用 CTA，并在 footer 显示具体原因。
- CTA 固定为“确认记一局”或“保存修改”，动态摘要移到按钮上方。
- 取消 chip 伪元素，改为 WXML 中显式“胜 / 负”标识。
- 320 三列；390 / 430 普通名四列、长名三列两行。
- 取消固定 88vh；中部唯一滚动，header / footer 固定。
- 移除 CSS 的第二层 safe-area 计算，保留 Vant popup 负责安全区。
- 同时修正全部 water sheet 原生确认按钮的半宽问题。

### 盲审 D

### 实现后综合决策

- 采纳共同 P1：侧别切换时仅重排一次，把当前侧成员置于首屏；单次点选保持显示顺序，避免控件跳位；搜索与清除保持同一顺序。
- 采纳滚动建议：恢复原生 scrollbar，并把名单提示改成带当前侧语义的“上下滑动”指引，不新增第二个滚动 owner。
- 采纳摘要建议：收起态只显示至多两个姓名和完整省略号，不再重复人数；展开态与 `aria-label` 保留完整阵容。
- 采纳关闭与对比度建议：补 ≥44px 可访问关闭按钮；保留旧全局 muted 色，仅在 game sheet 对关键小字使用对比度 ≥4.5:1 的 scoped strong-muted。
- 搜索图标本轮不扩成新图标资产；它是 P2，先保留文字搜索框和稳定的输入标签，后续有真实微信像素证据时再判断是否替换。

### 关闭复核

首轮实现后审查均为 NO-GO，修复后两名评审继续独立复核，期间又发现并关闭两个仅在交互链出现的 P1：

- 排序改为“当前侧已选 → 未分配 → 对侧已选”。首次从已选胜方切到空负方时，首屏先出现可加入负方的未分配成员；已有负方时先出现负方成员。
- 每次真正切换侧别时让 `scroll-top` 在 0 / 1 间翻转，强制从深滚动位置回到顶部；同侧点击不处理，连续点选、搜索和清除均保持显示顺序，避免名单跳位。
- 未激活 side tab 也使用 scoped strong-muted，关闭最后一处已知 24rpx 低对比问题。

两名评审最终均给出 **GO**，确认共同 P0 / P1 已关闭。残余 P2 为：读屏 `selectionLabel` 尚可进一步说明点击后的动作、Unicode 搜索符号和非拖拽把手可继续润色、footer 前半行裁切仍可更柔和。微信原生 `scroll-view`、safe-area、字体基线、键盘和字体放大仍属于真实 DevTools 像素验收缺口，不由浏览器近似稿关闭。
