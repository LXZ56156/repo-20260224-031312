# 0001 · 向后兼容云函数变更自动部署

> 状态：accepted
> 决策日期：2026-08-14
> 用户选择：兼容变更自动部署

## 决策

云函数代码提交后，如果变更满足下面的向后兼容合同，允许由受保护的 `post-commit` hook 自动部署，不需要为每个兼容提交重复申请部署授权。

不兼容变更、数据或环境变更、小程序客户端发布仍需单独明确授权。

## “兼容”的精确定义

必须同时满足：

1. 已发布旧版小程序仍可使用旧参数和旧调用路径。
2. 旧数据记录无需迁移即可继续读取和写入；缺少新字段时有安全默认值。
3. 既有 `ok/code/message/state/traceId/data` 返回 shape、错误码含义、权限和幂等语义不被破坏。
4. 新参数、新返回字段和新能力默认可选或默认关闭。
5. 默认路径不依赖尚未批准的新 collection、index、权限规则、secret、配置开关或真实数据初始化。
6. 不删除或重命名函数、字段、集合、事件；不执行不可逆迁移或批量数据写入。

自动化测试只能证明合同覆盖，没有能力独立判断所有产品语义。提交前仍必须由实现者列出旧客户端、旧参数、旧数据和返回合同的兼容证据。

## 自动部署门槛

现有链路按以下顺序 fail closed：

1. post-commit 只读取当前 commit 的 changed files。
2. 仅选择 `cloudfunctions/<name>/` 发生变化的已配置函数；共享模板变化会覆盖全部配置函数。
3. deploy 相关路径必须 clean；手改 `cloudfunctions/*/lib/*` 会被拒绝。
4. 共享模板变化必须通过 cloud-common 同步检查。
5. 运行 `npm run check` 和全量 `node:test`。
6. 验证 CloudBase 环境可达和 workflow evidence 可写。
7. 前述门槛全部通过后才逐函数部署并写入部署记录。

部署失败不会撤销已经创建的 Git commit。失败必须明确报告“commit 已创建、部署未完成”，修复后只能针对明确 commit/range 重试，不能盲目重复真实远程动作。

## 仍需单独授权

- 新增/修改 collection、index、数据库权限、secret、环境配置和功能开关。
- 不兼容 API、数据迁移、删除、重命名、回填和真实业务数据写入。
- `mp:preview`、preview delivery、`mp:upload`、审核提交和正式发布。
- 任何无法明确证明向后兼容的云函数变更。

## 停止开关

需要只提交、不部署时，使用 `SKIP_CLOUD_POST_COMMIT_DEPLOY=1`。该开关用于明确暂停、离线环境、文档/工具提交或不兼容变更准备，不应被用来掩盖兼容测试失败。
